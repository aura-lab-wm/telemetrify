Telemetrify · Final Spec · Design 04

AI-Pulse — Data-Viz Forward

The chosen direction, refined to ship. A 480px macOS menubar popover that reframes the four L40S GPUs as glanceable radial gauges with memory sparklines and a KPI pressure strip, plus a re-architected services list and a native log viewer. This page is the developer-facing deliverable: pixel-faithful mockups, the load-bearing layout rule, and SwiftUI handoff notes per section.

⚠ The bug this redesign fixes

Today each service row is a single card with the spotlight (view-logs) icon inside it. When a service is stopped, a Start button also appears inside the card and shoves the spotlight icon left — so the magnifier lands at a different x on every row and the list jitters whenever a service changes state. The fix is structural: the spotlight stays pinned inside the card, and the Start/Stop/Kill control moves to a fixed-width gutter column outside the card. Cards become identical width in every state; only the gutter glyph changes.

Implementation notes

  • Ring gauges = native Gauge(value:in:){}.gaugeStyle(.accessoryCircularCapacity), or Circle().trim(from:0,to:util) for full color control + the rotate(-90°) start.
  • Sparklines = tiny Chart { ForEach(samples){ BarMark } } (Swift Charts) fed a rolling buffer of recent polls; hide axes with .chartXAxis(.hidden).
  • KPI strip is derived state: avg util, free count, peak temp computed from the GPU array — never stored.
  • 2×2 grid = LazyVGrid(columns:[GridItem(.flexible()),GridItem(.flexible())]); gauges .fixedSize() so cards stay 480-bound.
  • Service row = HStack(spacing:8){ Card; Gutter } with Gutter.frame(width:44). See §02 for the full rule.
  • Model picker is a SwiftUI Menu indented under the vllm card — it lives in the card column, never the gutter.
  • NSPopover: set contentSize to a fixed 480 width; height .sizeThatFits. Behavior .transient.
02

The card + gutter rule

non-negotiable · apply to every service row

Every service row is an HStack of exactly two children: a flexible card and a fixed-width action gutter. The spotlight/log icon is permanently the trailing element inside the card; the Start/Stop/Kill control lives outside the card in the 44pt gutter. Because the gutter width is always reserved, every card renders at an identical width and the spotlight icon never moves — regardless of service state.

Card (flexible) — LED, name, status, then the spotlight. Width is identical in every state because the action never enters it.
Spotlight (in-card, trailing) — opens the log viewer. Anchored with Spacer() before it so it always hugs the card's right edge.
Gutter (fixed 44pt) — holds exactly one glyph: play.fill (stopped), stop.fill (running), spinner (transitioning), or a reserved ghost so width is constant.

SwiftUI shape of the rule

  • Row: HStack(spacing:8){ ServiceCard(svc); ActionGutter(svc).frame(width:44) } — the only place service state branches.
  • Card body ends with Spacer(minLength:8) then the spotlight Button, so the magnifier always trails at the card's right edge.
  • Gutter is a single switch svc.state: .running → stop.fill, .stopped → play.fill, .transitioning → ProgressView(), else → Color.clear ghost. The .frame(width:44) guarantees constant gutter width even for the ghost.
  • Never put the action Button inside ServiceCard. Card layout must be independent of state — verify by toggling state in a Preview and confirming the card's frame is identical.
  • Kill (force) is the long-press / right-click affordance on the running stop.fill gutter button, surfaced via .contextMenu with xmark.octagon.

Implementation notes

  • Detach as an NSPanel (.nonactivatingPanel, .titled, .fullSizeContentView) so the traffic-light close maps to a real window control; or push as a second NavigationStack route inside the popover for a lighter build.
  • Stream = ScrollViewReader { ScrollView { LazyVStack(lines) } }; on new line call proxy.scrollTo(last, anchor:.bottom) only while auto-scroll is on. Disable it when the user scrolls up (track via .onScrollPhaseChange / a drag gesture).
  • Lines are a struct LogLine { ts; level; text }. Level drives .foregroundStyle: .info → blue, .warn → orange, .error → red with a tinted row background.
  • Level chips = Set<LogLevel> filter; search is a .searchable-style TextField doing case-insensitive contains. Both filter the same derived visibleLines.
  • Copy = NSPasteboard of the visible (filtered) lines; Export writes the full buffer to ~/Library/Logs/AI-Pulse/<service>.log via a save panel.
  • Mono font: .system(.caption, design:.monospaced); tint inline tokens (paths, status codes, sizes) with AttributedString for the cyan/green highlights.
  • Use a bounded ring buffer (e.g. last 2,000 lines) so a chatty vllm doesn't grow memory unbounded.

Live stream mocks realistic vllm startup + serving lines (model load, CUDA alloc, OOM recovery, HTTP) and a rocco-agent health probe.
