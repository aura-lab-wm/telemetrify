vLLM Model Picker — keeping every card single-line & identical in shape

The vllm row is the only service that needs a model-selection control. Today it adds a second line inside the card, breaking the hard rule that cards are pixel-identical in width and height. Below are four ways to keep the model picker (and current-model info) accessible while every card stays a single fixed-height row. The summary text that currently duplicates the model name is removed in every option.

Recommended Option B — Compact In-Card Chip

The chip wins on the metrics that matter for a frequent operation: it is a single, obvious, button-shaped target (one click to open, one to pick), it lives on the vllm row where the operator expects it, and its fixed 24pt height guarantees the card never grows — satisfying the "same shape always" rule without pushing other rows around like the disclosure (C) does. It also fixes the duplication: the chip owns the model identity, freeing the summary to show live telemetry (2 GPUs · 18k ctx) instead of the ugly mid-truncated name. The "capped by training" hint reads naturally as the small orange warning glyph beside the chip, with the full reason in the menu. Option A is the strong runner-up and shares the same chrome philosophy — if abbreviation rules feel fragile, fall back to A's underlined-text picker, which needs no truncation logic at all.
